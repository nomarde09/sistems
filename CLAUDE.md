# CLAUDE.md

Инструкции для Claude Code при работе с этим репозиторием.

## О проекте

«Система заявок»: приложение для приёма и обработки заявок. Цели, роли, модель данных и план работ описаны в [PROJECT.md](PROJECT.md). Перед крупными изменениями сверяйся с ним, а после выполнения пункта плана отмечай его там.

Пользователь не программист. Всю техническую работу (код, установка, запуск, тесты, исправления) делает Claude. Не давай пользователю инструкций вида «создай файл» или «запусти команду». Если без его действия не обойтись (хостинг, оплата), объясни по шагам простыми словами.

После каждого этапа из PROJECT.md: сам проверь работу (автотесты и браузер), затем коротко напиши, что можно посмотреть и как открыть.

Стек выбран: Python + Flask, данные в SQLite. Новые зависимости и крупные смены подхода сначала согласуй с пользователем.

## Структура

```
app.py             — вся программа: входы, страницы, правила доступа, лог приложения
tech.py            — технический раздел суперадмина (/tech): вход из .env, статистика, журнал, лог; только чтение
stats.py           — расчёт сквозной статистики (общий для руководителя /ofis/statistika и /tech)
templates/tech/    — страницы технического раздела
templates/         — страницы (HTML-шаблоны Jinja)
tests/             — автопроверки (unittest): test_app.py — вход, заявки, бригады, отчёт;
                     test_boss.py — исправление, отмена, поиск, весь путь заявки;
                     test_payment.py — способ оплаты, срочные наверху;
                     test_tabs.py — вкладки статусов в офисе;
                     test_tech.py — технический раздел: изоляция, скрытность, только чтение;
                     test_boss_stats.py — статистика руководителя (совпадает с техразделом);
                     test_location.py — геолокация: ссылки, координаты, кнопки карты;
                     test_stats_periods.py — статистика по периодам и с именами;
                     test_request_fields.py — тип заявки, оборудование, время, гарантия
static/style.css   — оформление
static/*.png, manifest.webmanifest — значок для «добавить на главный экран»
requirements.txt   — зависимости
.env               — секретный ключ и пароли входа (создаётся сам, не в git)
.env.example       — пример .env
data/              — база заявок и data/logs/app.log (не в git)
.claude/launch.json — запуск для превью в Claude Code (имя "zayavki")
```

**Технический раздел.** Суперадмин не входит в `USERS` и нигде не показывается сотрудникам. Логин и пароль — только `SUPERADMIN_LOGIN` / `SUPERADMIN_PASSWORD` в `.env` (пароль от 12 символов, иначе раздел отвечает 404). Сессия отдельная (`tech_admin`, 8 часов), 5 ошибок входа — блок на 15 минут. В разделе только чтение: POST разрешён лишь для входа и выхода (это проверяет тест). Пароль суперадмина не читай и не выводи. Лог приложения не должен содержать паролей, текстов заявок и строк поиска.

Пользователи заданы в `USERS` в `app.py`, роли: `boss` (руководитель), `office` (менеджер), `brigade` (бригада). Вход — поля «логин» и «пароль» (список сотрудников на странице входа не показывается). Логин: `LOGIN_<ID>` в `.env`, по умолчанию сам `<ID>`, регистр не важен. Пароли: `PIN_<ID>` в `.env` (ключ строго латиницей: `PIN_MANAGER1`, не `PIN_Яна`). Имя человека (`NAME_<ID>` в `.env`, без него — должность) показывается везде: шапка, списки, фильтры, журнал, статистика, техраздел — через фильтр шаблонов `who`. Подписи действий без рода: «Взял(а)», «Выполнил(а)». Автопроверки задают свои логины, имена и пароли и от рабочего `.env` не зависят. 5 неверных паролей к одному логину с одного адреса — пауза 15 минут. Адреса страниц на латинице транслитом: `/vhod`, `/ofis`, `/brigada`.

**Поля заявки.** Тип заявки и оборудование — ключи из `REQUEST_TYPES` / `EQUIPMENT` в `app.py` (в базе хранится ключ; ключи не переименовывать — по ним считается статистика, подписи менять можно). `warranty` 0/1, при создании всегда 0, меняется в карточке (`/zayavka/<id>/garantiya`, руководитель и менеджеры) или через «Исправить». `agreed_time` — «ЧЧ:ММ» из `AGREED_TIMES`. `work_type` устарело: только у старых заявок, у новых пустая строка.

## Команды

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python app.py        # сайт на http://localhost:5000
.venv/Scripts/python -m unittest discover -s tests -v   # автопроверки
```

Автопроверки (`tests/test_app.py`) работают на временной базе. После каждого изменения прогоняй их, на каждый новый этап добавляй свои. Все формы с POST должны содержать скрытое поле `csrf` (`{{ csrf_token() }}`), иначе сервер ответит 400.

Время хранится как местное, пояс задаёт `TZ_OFFSET_HOURS` в `.env`. После правки `.env` сайт нужно перезапустить целиком (остановить и запустить превью), автоперезагрузка его не перечитывает.

Для проверки в браузере используй превью `zayavki`. Для показа с телефона в той же Wi-Fi сети — превью `zayavki-telefon` (`app.py --telefon`: слушает 0.0.0.0:5000, режим разработчика выключен); адрес компьютера в сети смотри через `Get-NetIPConfiguration`. Брандмауэр Windows не трогай: разрешение на входящие подключения даёт пользователь сам. Не показывай пароли из `.env` в чате, отсылай пользователя к файлу.
