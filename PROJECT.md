# PROJECT: Система заявок

Описание проекта: зачем он нужен, что должен уметь и в каком порядке его делать. Разделы с пометкой «уточнить» нужно заполнить.

## Цель

Дать единое место, где заявки принимаются, распределяются между исполнителями и доводятся до результата, чтобы ни одна заявка не потерялась.

## Пользователи и роли

| Роль | Что может |
|---|---|
| Заявитель | Создаёт заявки, видит их статус, пишет комментарии |
| Исполнитель | Берёт заявки в работу, меняет статус, отвечает |
| Администратор | Управляет пользователями, категориями, назначает исполнителей |

_Уточнить: нужны ли другие роли (например, руководитель с отчётами)._

## Основной сценарий

1. Заявитель создаёт заявку: тема, описание, категория, приоритет.
2. Заявка получает статус **«Новая»**.
3. Администратор или исполнитель назначает ответственного → **«В работе»**.
4. Исполнитель решает задачу → **«Выполнена»** (или **«Отклонена»** с причиной).
5. Заявитель видит результат; при необходимости заявку можно открыть повторно.

## Модель данных (черновик)

- **User**: id, имя, email, роль
- **Request** (заявка): id, тема, описание, категория, приоритет, статус, автор, исполнитель, даты создания/обновления/закрытия
- **Comment**: id, заявка, автор, текст, дата
- **StatusHistory**: id, заявка, старый статус, новый статус, кто изменил, когда
